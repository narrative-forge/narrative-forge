# ADR-002：JSON + Zod 作为 Schema 格式

- 状态：已采纳（Accepted）
- 日期：2024 年第零阶段
- 决策人：Narrative Forge 核心组

## 背景

视频内容需要一种**声明式、可移植**的结构描述（场景、布局、时序、素材引用等）。
该描述需同时服务于：类型推导、运行时校验、以及跨包（schema → core → render）共享。

## 选项

1. **JSON（序列化）+ Zod（校验/类型）**：JSON 负责存储与交换，Zod 作为单一数据源生成 TS 类型并做运行时校验。
2. **YAML**：可读性更好，但工具链与类型推导较弱，且缩进敏感易错。
3. **专有 DSL**：表达力强，但需自建解析器，维护成本高。
4. **直接用 TypeScript 类型**：类型安全，但缺少可序列化的"数据"形态，难以作为配置/资产存储。

## 决定

采用 **JSON 作为序列化格式，Zod 作为运行时校验与类型推导的单一数据源**。

## 理由

- JSON 工具链成熟、可移植、可被任意语言读取。
- Zod schema 一处定义，同时产出 TS 类型与运行时校验，避免"类型与校验双份维护"。
- 与 Remotion/TypeScript 技术栈天然契合（见 ADR-001）。
- 校验失败能在渲染前（而非渲染中）暴露，配合 ADR-005 的确定性要求。

## 推翻条件

- 需要注释、复杂表达力或 human-friendly 编辑体验，YAML 明显更优；
- 出现更紧凑/更高效的二进制 Schema 格式且收益显著；
- 跨语言消费方普遍要求非 JSON 格式。

> 注：Schema 规范文档本身由 TASK-004 单独编写，本 ADR 仅确定格式取向。

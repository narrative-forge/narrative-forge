# ADR-004：布局与渲染分离

- 状态：已采纳（Accepted）
- 日期：2024 年第零阶段
- 决策人：Narrative Forge 核心组

## 背景

视频的"结构描述"（场景布局、元素排布、时序）与"像素级渲染实现"关注点不同。
若将二者耦合，渲染后端的替换/演进会影响上层结构定义，反之亦然。

## 选项

1. **分离**：布局层为声明式、框架无关的描述；渲染层（Remotion）消费布局并产出画面。
2. **耦合**：布局直接以 Remotion 组件表达，结构与渲染合一。

## 决定

采用 **布局与渲染分离**：

- `packages/layouts`（`@forge/layouts`）定义框架无关的布局原语与组合规则；
- `packages/render`（`@forge/render`）将布局映射为 Remotion 实现并输出视频；
- 两者通过 `@forge/schema` 定义的契约通信。

## 理由

- 可替换渲染后端（未来若换渲染引擎，布局层不受影响）。
- 布局层可独立单元测试，无需启动渲染。
- 关注点分离，符合 ADR-003 的模块化与 ADR-002 的契约驱动思路。
- 为"渲染侧不接 AI"（ADR-005）提供清晰的边界。

## 推翻条件

- 分离带来的接口维护/性能开销明显超过其收益；
- 出现某种"布局即渲染"的范式使耦合反而更简单且可控。

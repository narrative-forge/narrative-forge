对方的差评**不能**记在 TASK-009 的账上。这条链的每一环都有据可查：

### 2.1 容器与流参数（ffprobe 实测 vs 声明）

| 项 | 声明（`stories/demo/huining-1936.json` / `Root.tsx`） | 实测 | 判定 |
|---|---|---|---|
| 分辨率 | `meta.resolution: "1920x1080"` | 1920x1080 | ✅ |
| 帧率 | `fps: 30` | 30/1 | ✅ |
| 时长 | `schedule.totalSec = 98.050` → `durationInFrames = 2942` | 98.066667 s | ✅ |
| 编码 | Remotion 默认 h264 | h264 | ✅ |
| 文件 | — | 2,672,965 B / 218 kbps | ✅ 体积正常 |

复算：`totalSec = 0.8 + Σ(10 + 0.05×(label+desc).length) + 1.0 = 98.050`；
`ceil(98.050 × 30) = ceil(2941.5) = 2942`。MP4 的 98.066667 s 就是 `2942 / 30`，
即**帧数取整后**的容器时长，与调度值相差半帧（0.0167 s），属正常，不是缺陷。

> **修订（2026-10-07，TASK-012 期间）**：本节初稿把 ffprobe 读到的容器时长
> `98.067` 误写成了 `schedule.totalSec`。调度值是 **98.050**，容器值是
> `2942 / 30 = 98.067` —— 两者来源不同（一个是节奏函数，一个是帧数），
> 不应混用。§3.11 与 §7 复算脚本中的同一处笔误已一并更正。

## 3. "一坨屎"的定量拆解

### 3.1 画面 **83.3%** 是空载

抽帧 `demo-40s.png` 里，全部信息集中在中部一条横带上：

```
y = 0    ┌──────────────────────────┐
         │                          │
y = 252  │   ▁▁▁▁▁▁ 卡片顶边 ▁▁▁▁▁▁  │  ← 上方留白 252px（23.3%）
y = 432  │   ▔▔▔▔▔▔ 卡片底边 ▔▔▔▔▔▔  │  ← 卡片高 180px（16.7%）
y = 648  │   ────────────────────   │  ← timelineY = 0.6H
         │                          │
y = 1080 └──────────────────────────┘  ← 下方留白 432px（40.0%）
```

- **有效像素占比 = 180 / 1080 = 16.7%** → 空载 **83.3%**
- 下方 40% 的空白本来可以承载**旁白字幕**，但没有旁白（§3.8）
- 上方 23.3% 本该是标题区 / 年份刻度，实际什么都没有（§3.7）

**根因**：垂直方向**没有任何版式设计**。全屏只有一个 `timelineY = height * 0.6`
（`layouts/timeline.ts:45`）的硬编码比例，其余全靠 `AbsoluteFill` 的默认背景色。

### 3.2 卡片重叠 —— 几何上**必然发生**（最关键的一条）

这是 TASK-007 §1.3 声称"满足人工审查『不重叠』"的地方，但它**实际是重叠的**。

**算式**（8 节点 / 1920 宽 / paddingX 80）：

```
间距 spacing = (1920 − 2×80) / (8 − 1) = 1760 / 7 = 251.43 px
fitScale    = min(1, 251.43 / 320)                = 0.7857
非活动卡有效宽 = 320 × 0.7857 = 251.43 px   ← 恰好等于间距 → 相邻卡间隙 = 0 px
活动卡宽      = 320 px（scale = 1）
              → 超出间距 68.57 px → 向左、右各压住邻居 34.29 px  ← 必然遮挡
```

`TimelineComposition.tsx:109` 就是元凶：

```ts
const scale = isActive ? 1 : fitScale;   // 活动卡拒绝缩放
```

实拍证据：`demo-40s.png` 中「**红二、六军团甘孜会师**」标题的右半被活动卡
「红二方面军成立」压掉；`demo-55s.png` 中「红一、四方面军会宁会师」被压。
**这是一个真 bug，不是审美偏好。**

附带问题：相邻非活动卡**间隙恰为 0 px** → 8 张卡连成一堵**无呼吸的文字墙**，
配合 §3.6 的 0.4 透明度，观感就是"糊成一片"。

### 3.3 卡片纵向错落 —— `transform` 组合 bug

```tsx
// TimelineComposition.tsx:117  外层：整体平移
transform: 'translate(-50%, -120%)'
// EventCard.tsx:54             内层：自身中心缩放
transform: `scale(${scale})`
```

`scale()` 的默认 `transform-origin` 是**元素自身中心**。卡片中心固定在
`y = 432 − 90 = 342`，缩放只改高度、不改中心：

| | 顶边 | 底边 | 高度 |
|---|---|---|---|
| 活动卡（scale = 1） | 252 | 432 | 180 |
| 非活动卡（scale = 0.7857） | **271.3** | **412.7** | 141.4 |

→ 相邻卡片上下**各错开 19.3 px**。抽帧中那一排卡片"参差不齐"就是这 19.3 px。
**也是真 bug。**

### 3.4 正文字号低于平台可读下限

| 元素 | 当前 | 占屏宽 | 抖音/快手横屏 1080p 经验下限 | 差距 |
|---|---|---|---|---|
| 事件标签 | 32 px | 1.67% | ≈ 48 px | 低 33% |
| 事件描述 | 20 px | 1.04% | ≈ 40 px | **低 50%** |

以 1920 宽横屏视频在手机上全屏观看计，20 px 中文的物理字高约 0.6 mm；
正常阅读下限约 1.5–2 mm。**差约 3 倍。** 抽帧里描述文字必须放大截图才能辨认，
这不是观感问题，是**信息不可达**。

**根因**：`tokens.ts:21-22` 的 `eventLabelSize / eventDescSize` 是按
"Studio 预览能看清"定的，不是按"手机竖屏能看清"定的。

### 3.5 时间轴对比度 **1.49 : 1**，等于不可见

WCAG 对非文本图形元素要求对比度 ≥ **3 : 1**（正文要求 4.5 : 1）。

```
#2a3144 相对亮度 L = 0.0316     #0a0e1a 相对亮度 L = 0.0053
对比度 = (0.0316 + 0.05) / (0.0053 + 0.05) = 0.0816 / 0.0553 = 1.49 : 1
```

线宽 4 px（`Timeline.tsx:47`）。抽帧里这条线**基本看不到**，只剩几个灰点
（`#6b7280` → 3.98 : 1，勉强过图形 3 : 1 线）。**一条"看不见的时间轴"是"时间线视频"的**
**核心表达失效。** 真 bug。

### 3.6 非活动卡 `opacity: 0.4` —— 让**重点标记反而最不可读**

`layouts/timeline.ts:92`：

```ts
const opacity = inIntro || inOutro ? 0.5 : node.id === activeNodeId ? 1.0 : 0.4;
```

实测各元素**混合后的真实对比度**（`bg = #0a0e1a`）：

| 元素 | 不透明度 | 最终对比度 | WCAG 4.5:1 | 判定 |
|---|---|---|---|---|
| 活动卡标签 | 1.0 | 16.01 : 1 | ✅ | 优秀 |
| 非活动卡标签 | 0.72（建议值） | 8.52 : 1 | ✅ | 合格 |
| **非活动卡标签** | **0.40（现状）** | **3.36 : 1** | ❌ | 正文不达标 |
| 非活动卡描述 | 0.8 × 0.40 = 0.32 | **2.56 : 1** | ❌ | **严重不达标** |
| **非活动 featured 金标** | **0.40** | **2.25 : 1** | ❌ | **最不可读** |

最后一行最讽刺：`accent` 金色标记的**全部意义**就是"这是关键节点"，但在非活动态
它只有 2.25 : 1 —— **八张卡里唯一该被看见的两张（会宁会师、三大主力会师完成），**
**在大部分时间里是最看不清的两张。**

（"降透明 = 表达聚焦"的意图没错，错在把**可读性**当成了层级手段；应改用
降饱和度 / 变暗边框 / 移出焦点位来表达层级，正文对比度保住。）

抽帧 `demo-40s.png` 左起两张卡已几乎融进背景，与此数值完全吻合。

### 3.7 时间信息**零呈现** —— 最伤的一条

数据里 8 个节点**都带 `time`**：

```
1935-10-19 · 1936-05-01 · 1936-07-02 · 1936-07-05
1936-08-01 · 1936-10-09 · 1936-10-15 · 1936-10-22
```

而 `TimelineComposition.tsx:121-127` 传给 `EventCard` 的只有
`label / description / featured / active`——**`time` 一次都没传进渲染层。**

后果：观众看不到这条线是 **1935-10 → 1936-10**，看不到每站隔了多久，
**"时间线"退化成"一排并行卡片"**。而 `time` 在 schema 里是**必填字段**
（`zod.ts:64`）——一个必填字段被渲染层整体无视，属于功能缺失。

同理被无视的还有：`views[].tracks`、`node.track`、`edges[]`（7 条 `temporal` 边）。

### 3.8 无音轨 —— **但 schema 支持**

`ffprobe -select_streams a` 返回**空**：MP4 内 0 条音频流。

但这不是管线缺陷：

```ts
// packages/schema/src/zod.ts
MetaSchema:  bgm: AssetIdSchema.optional()        // ← 支持 BGM
AssetSchema: type: z.enum(['image','audio','video'])  // ← 支持音频资产
StorySchema: assets: z.array(AssetSchema)         // ← 支持资产表
```

demo 数据里 `meta` 无 `bgm`、`assets: []` → **是数据没喂，不是管线不能喂。**

**真正的问题在时长模型**：`perCharSec = 0.05` + `baseSec = 10` 把 8 个节点撑到
98 秒，这个节奏是**为"有人念出来"设计的**（按字数计秒），但**声音不存在**。
→ 观众在等一句永远不会来的话，**这就是"屎"感的最大来源**。

### 3.9 零素材 —— 同样是数据空缺

```json
"nodes": [ { "media": [] }, ... 8 个全是空 ]
"assets": []
```

对"地方知识科普"这个定位，**没有一张实景、没有一张档案图、没有一段音乐**，
全部是纯文字卡。这属于内容层空缺（`phase-1-scope.md` §2 明确"Phase 1 不写 View 规范"），
但它是画面单薄的决定性因素。

### 3.10 相机是**匀速 lerp**，不是缓动

```ts
// packages/compositions/src/camera.ts:18-20
function lerp(a, b, t) { return a + (b - a) * t; }
```

文件头注释写着 "TASK-007 smooths the motion via Remotion springs/interpolate"，
但实现是**纯线性插值**，没有 spring、没有 easing。

→ 每次镜头切换都是"**突然开始匀速滑、突然停住**"。这就是画面"机械、廉价"的来源，
也解释了为什么 7 张抽帧看起来像"同一张图的不同横向偏移"。

### 3.11 每屏静置 **12 秒**，全程零动效

```
每节点时长 = (98.050 − 0.8 − 1.0) / 8 = 12.031 s
```

98 秒里，画面的**唯一**变化是：水平匀速平移（每 12 秒一次）+ 卡片透明度切换。
没有卡片入场、没有节点逐个点亮、没有高亮脉冲、没有转场。

**短视频平台的现实**：静置 12 秒 = 用户划走。这条视频的留存曲线可以预判为断崖。

### 3.12 片头写了数据里不存在的 **1934**

```tsx
// TimelineComposition.tsx:67
subtitle={isIntro ? '1934 — 1936 · 长征会师' : '—— 完 ——'}
```

而数据首节点是 **1935-10-19**，全部 8 个节点没有任何 1934 年的事件。

（长征确于 1934-10 开始，作为笼统年代区间不算硬错；但按本仓库
「每个数字都要有来源」的口径，**画面上的年份应当由数据推出，而不是字符串硬编码**。
`title` 同理：intro 与 outro 用同一个 `story.meta.title`，共约 1.8 s 内出现两次同一张卡。）

### 3.13 隐藏隐患：描述过长会被**静默裁切**

`EventCard.tsx:53` 有 `overflow: 'hidden'`，卡高固定 180 px。
按当前字号，卡片最多容纳约 3 行描述。而 `metadata` 在 schema 里是
`z.record(z.string(), z.unknown())` —— **`description` 长度完全无约束**。
→ 只要有一条描述超过 3 行，就会被**无声裁掉**，不报错、不告警。

## 4. 归因：**不是管线失败，是"自检样片被当成作品看"**

这一点有仓库文档背书，不是我在找补：

| 出处 | 原文 | 含义 |
|---|---|---|
| `docs/specs/phase-1-scope.md` §1 | 「**迁移验证示例**：以会宁会师数据作为首个**端到端验证样例**」 | demo 的使命是"验证管线" |
| 同上 §3 DoD | 「会宁会师示例数据可在最小渲染管线下**端到端跑通**（验证迁移与节奏调度）」 | **只字未提画面** |
| 同上 §2 | 「**不写 View 规范文档**（Phase 2 再写）」 | 视觉规范**明确排除在 Phase 1 之外** |
| `TASK-007-report.md` §1.3 | 「事件卡按节点间距自适应缩放……**满足人工审查"不重叠"**」 | 视觉决策的出发点是**过验收门**，不是好看 |
| `docs/adr/ADR-005` | 渲染管线不接入 AI | 画面不会自己变好 |

**所以**：
- 对方说"一坨屎" → **判断正确**（以成片标准衡量，§3 的 12 条全部成立）
- 对方隐含的定性"你们做砸了" → **不成立**（管线 4/4 达标，§2）
- 真实缺口：**从没有人立项做视觉**。Phase 1 的 DoD 里根本没有"好看"这两个字。

## 6. 需要拍板的三个问题（**方向未定前不宜动代码**）

### Q1. 这版 demo 的交付定位是什么？

| 选项 | 含义 | 后续动作 |
|---|---|---|
| **A. 就是管线自检** | 画面不重要，只要能跑 | 只修 §5 的 P0（8 条真 bug），画面保持简朴，**并在 README/交付说明里标明"非成片"** |
| **B. 要变成可发布的成片** | 那就要正式立"视觉规范"任务 | 依次做 P0 → P1 → P2，需要先定 Q2 |

> 我的建议：**先做 A（修 P0），再做 B**。P0 的 8 条改动不依赖任何内容决策，
> 且修完画面至少从"错乱"回到"干净"，是后续所有设计工作的地基。

### Q2. 画幅是横屏还是竖屏？

- 现状：`1920x1080` 横屏。8 节点铺满 1920 宽、间距 251 px 的**一切几何冲突都源于此**。
- 若改 **`1080x1920` 竖屏**（抖音/快手原生）：时间轴应改为**纵向**，每屏只放 3–4 个节点，
  卡片叠放而非并排 → 字号问题、重叠问题、留白问题**一次性全部消解**。
- 代价：`zod.ts` 的 `resolution` 枚举要扩，`computeTimelineLayout` 要做纵向版本（`layout: 'vertical'`），
  现有测试要同步。

> 这一条的决定权在内容侧，不在工程侧。**我倾向竖屏**——目标平台是抖音/快手。

### Q3. 有没有旁白？

- **有旁白**（TTS 或人声）→ 98 秒成立，`perCharSec` 模型正好是它的时长来源；
  但需要补：字幕条（画面下方那 40% 空白正好用上）、音画对齐（R-05 风险）。
- **无旁白** → 视频必须按"可静音观看"重做：压时长、上素材、加动效与字幕。

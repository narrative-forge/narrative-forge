## 2. 几何验算（改动后的常数）

```
spacing  = (1920 − 2×120) / (8 − 1) = 240 px
fitScale = min(1, 240 / 260) × 0.92  = 0.849
有效卡宽 = 260 × 0.849 = 220.8 px  → 相邻间隙 19.2 px   （原：0 px）
活动卡宽 = 220.8 px < 240 px        → 不压邻居           （原：压 34.29 px/侧）
```

| 元素 | 原 | 新 | 说明 |
|---|---|---|---|
| 卡片纵向错落 | 19.3 px | **0** | 所有卡片共用同一 `scale`，缩放不再改变各自的中心偏移 |
| 事件标签有效字号 | 25.1 px | **40.8 px** | 48 × 0.849（原 32 × 0.7857） |
| 描述有效字号 | 15.7 px | **36 px** | 移入字幕条，**不再被缩放** |
| 时间轴对比度 | 1.49 : 1 | **3.41 : 1** | WCAG 非文本图形要求 ≥ 3 : 1 |
| 非活动卡正文对比度 | 2.56 : 1 | 达标 | 见 §1 |

### 3.1 两处需要说明的取舍

**① 描述从卡片搬到了字幕条。**
卡片整体要乘 `fitScale`（≈0.85），把正文留在卡片里，字号再怎么提都会被缩回去 —— 20px 乘 0.79 只剩 15.7px。移到未被缩放的字幕条后，36px 才是真实呈现值。副作用是卡片变薄（只放年份 + 标签），这恰好让它能收窄到 260px，从而不再压邻居。**三个问题由同一个改动解决。**

**② 活动卡不再放大。**
`scale = isActive ? 1 : fitScale` 是"重叠"的直接原因。焦点改用边框亮度、金色光晕、背景提亮三者表达 —— 这也顺带消除了 19.3px 的纵向错落（TASK-011 §3.3）。
